# Архитектура и развитие

## Поток данных

1. `discover` проходит `/proMatches` по `less_than_match_id`, проверяет обязательные
   поля и исключает дубли между страницами.
2. `sync` применяет список `LEAGUE_IDS`, обновляет справочник героев и сохраняет
   обнаруженные матчи в `raw.pro_matches`.
3. Очередь строится из raw: отсутствующие подробности и свежие матчи с пустым драфтом.
   Каждый запрос `/matches/{id}` проверяется и сохраняется отдельной транзакцией.
4. Airflow запускает `dbt build` после успешного сбора. dbt разворачивает JSON,
   строит таблицы результатов и проверяет ключи/ссылки/метрики.
5. Дашборд читает витрины с параметризованными SQL-фильтрами. Кэш ограничен 60 секундами.

Raw хранится в отдельной схеме, метаданные Airflow — в отдельной базе `airflow`.
Упрощённый локальный стенд использует одну роль PostgreSQL. dbt живёт в отдельном venv.

## Семантика аналитики

- `radiant_win` определяет победителя; Dire получает противоположный исход.
- `picks_bans.team`: 0 — Radiant, 1 — Dire. Команда, совершившая действие,
  определяется через сторону в конкретном матче, а не имя команды.
- Командные витрины исключают сторону без валидного `team_id`.
- Имена могут меняться; агрегаты сохраняют исторические названия, а ключом команды
  является ID. Текущая версия не объединяет переименования под одной канонической подписью.
- `patch_id` сохраняется, когда присутствует, но интерфейс пока не включает сравнение патчей.

## Границы MVP

Список последних страниц не является гарантированным журналом всех матчей.
Tier-1 задаётся пользователем через ID турниров. Драфт не подменяется данными
из состава игроков: при отсутствии настоящего порядка событий статистика драфта неполна.
Модели отвечают на описательные вопросы и не предсказывают победителя.

## Следующие шаги

1. Версионируемый справочник tier-1 турниров и автоматический backfill до границы времени.
2. Статус попыток по каждому матчу и отдельная очередь для ошибок/неполных драфтов.
3. Учёт серий, канонические названия команд и сравнение по патчам.
4. Incremental dbt-модели, freshness/coverage проверки, отдельная роль БД для дашборда.
5. Отдельные сервисы Airflow, безопасное управление секретами и мониторинг для production.
